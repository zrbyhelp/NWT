# AI 配置

AI 配置按当前登录账号隔离。每个账号可以维护自己的 OpenAI-compatible 供应商、LLM 模型、向量模型、图片模型和语音模型。管理员还可以把 LLM、向量、图片和语音模型设为“通用”，通用模型使用管理员供应商与 API Key，所有用户可见且可用。

## 供应商

供应商保存以下信息：

- 名称
- 标识
- Base URL
- API Key
- 启用状态

API Key 使用 `AI_CONFIG_ENCRYPTION_KEY` 加密后写入数据库。编辑供应商时不会回显明文，只能重填或清空。

## LLM 模型

LLM 模型用于首页聊天回复。字段包括：

- 供应商
- 显示名称
- 模型 ID
- 默认温度
- 启用状态
- 是否默认
- 是否通用（仅管理员）

默认 LLM 遵循个人优先、通用兜底：当前账号有可用个人默认时使用个人默认；没有个人默认时使用管理员设置的通用默认。若两者都不存在，系统不会用 `.env.local` 代替，而会提示用户前往右上角“设置”配置 LLM 模型。

若默认 LLM 所属供应商缺少 API Key，也会提示前往“AI 供应商”页补全配置。`.env.local` 中的 `OPENAI_BASE_URL`、`OPENAI_API_KEY`、`OPENAI_MODEL` 只作为没有用户上下文的内部兜底配置。

场景 AI 辅助和物品 AI 辅助都支持一次性参考图；默认 LLM 需要兼容 OpenAI `image_url` 多模态消息。若模型不支持图片输入，前端会提示切换支持读图的 LLM。

## 向量模型

向量模型用于后续文本切分、语义检索和 Qdrant 写入。字段包括：

- 供应商
- 显示名称
- 模型 ID
- 向量维度
- 最大输入 tokens
- 启用状态
- 是否默认
- 是否通用（仅管理员）

当前版本先完成配置、启停和默认项管理；默认选择同样遵循个人默认优先、管理员通用默认兜底。

## 图片模型

图片模型用于后续封面、场景图、角色图和场景全景生成。图片生成会按默认图片模型匹配调用预设：豆包/Seedream 与通用 OpenAI-compatible 服务优先直接请求 4K 尺寸，OpenAI 官方 `gpt-image-2` 场景全景使用 `3840x1920` 母图、`2880x2880` 六面图并显式传入 `quality: "high"`，其他 OpenAI 官方模型使用其支持的尺寸并在本地归一到项目目标，Gemini 原生接口使用 `generateContent` 的画幅和清晰度选项。假面设定板默认归一为 `3840x2160` 的 4K 16:9 横版，非 `gpt-image-2` 场景全景默认归一为 `4096x2048` 全景母图和 `4096x4096` 六面图。字段包括：

物品设定板生成和场景母图生成可传一次性参考图。OpenAI-compatible 图片接口会把参考图作为 `image` 参数传递，Gemini 原生接口会把参考图作为 `generateContent` 的图片 part；默认图片模型如果不支持图片参考，会在物品或场景生成处提示用户切换模型。

区块全景生成会使用流式接口回传阶段进度、母图、六面图、质检状态和最终色彩统一状态；母图是区块级资产，可单独保存并随素材导出导入。生成按钮左侧可设置最多迭代轮次，默认 1 轮，范围为 1-10 轮。图片生成链路不再设置额外请求超时；InstantMesh 任务超时和供应商模型列表拉取超时仍按各自配置执行。服务端会先按 10% 环绕条带搜索母图低复杂度切口并水平滚动到最佳 seam，再锁定接缝质检阶段的最佳轮次；六面高清化会把靠边约 5% 的拼接带锚定回母图切面，并以母图切面作为低频色彩权威对最终六面图做色彩转移和窄接缝均衡。色彩统一后会再次复检，若完整接缝指标变差则回退到统一前的最佳六面结果。生成的全景母图与六面图仍输出 WebP，但不再为了压到 10MB 内而降低质量；手动上传的普通素材、参考图和全景图仍保留 10MB 校验。

最多迭代轮次同时作用于母图 gate 和六面结构重绘。母图每轮生成后会先做左右环绕稳定，再检测 wrap 色差、亮度差、条带差、地平线代理偏移和 seam 复杂度；全部轮次仍未通过时会返回评分最高的母图并标记质检失败，用户仍可继续生成六面图。接缝质检把问题分为色差型和结构错位型，色差型先走本地修复且不消耗 AI 重绘次数，结构错位才进入定向重绘。

- 供应商
- 显示名称
- 模型 ID
- 启用状态
- 是否默认
- 是否通用（仅管理员）

当前版本先完成配置、启停和默认项管理；默认选择同样遵循个人默认优先、管理员通用默认兜底，具体图片生成工作流已接入封面、假面设定板和场景全景的生成链路。

## 语音模型

语音模型用于后续文本转语音、语音识别和角色声音生成。字段包括：

- 供应商
- 显示名称
- 模型 ID
- 启用状态
- 是否默认
- 是否通用（仅管理员）

当前版本先完成配置、启停、默认项管理和系统级预设识别；默认选择同样遵循个人默认优先、管理员通用默认兜底。后续语音生成或识别链路接入时，会优先读取当前账号的默认语音模型。

语音模型预设与图片模型预设采用相同思路：系统会根据供应商名称、Base URL 和模型 ID 自动识别常见模型族，供后续调用链路选择传输方式和能力类型。当前已内置小米 MiMo、OpenAI TTS/Whisper、通义/Qwen、CosyVoice、Fish Speech 和 SenseVoice 识别规则。小米语音 AI 会识别 `xiaomi`、`mimo`、`小米`、`platform.xiaomimimo.com`，并兼容 `MiMo-V2-TTS`、`MiMo-V2.5-TTS`、`MiMo-V2.5-TTS-VoiceDesign`、`MiMo-V2.5-TTS-VoiceClone`、`MiMo-V2.5-ASR` 等命名。该预设层目前只用于配置识别和后续调用准备，不代表已经完成语音生成运行时。

## InstantMesh Adapter

官方 InstantMesh 运行的是 Gradio Demo，不直接提供 NWT 需要的异步 REST 接口。项目单独提供本地适配服务 `tools/instantmesh-adapter`，由 FastAPI 包装 Gradio 调用，并向 NWT 暴露标准任务接口。适配器会读取 Gradio `/config` 自动识别当前“一步生成 GLB”的 workflow；遇到旧版三步 Demo 时会回退到预处理、多视图和 GLB 导出的旧调用链路。

本地默认填写：

- 名称：`本地 InstantMesh Adapter`
- Base URL：`http://localhost:3002`
- API Key：`local-dev`
- 提交路径：`/api/instantmesh/tasks`
- 状态路径模板：`/api/instantmesh/tasks/{taskId}`
- 轮询间隔毫秒：`1500`
- 超时秒数：`900`

Adapter 内部默认调用官方 Gradio 地址 `http://localhost:43839`。NWT 只提交单张 `modelInputImage`，不再提交前、后、左、右、上、下六张图；旧素材中的六视图只作为历史展示和导入导出兼容资产保留。

## 模型列表

新增或编辑模型时，前端会请求服务端动作，由服务端使用当前账号保存的 API Key 请求：

```text
{baseUrl}/models
```

返回列表会做基础分类：

- LLM：常见聊天模型，如 `gpt`、`qwen`、`deepseek`、`claude`。
- 向量模型：常见 embedding 模型，如 `embedding`、`bge`、`e5`。
- 图片模型：常见图片模型，如 `gpt-image`、`dall-e`、`flux`、`stable-diffusion`。
- 语音模型：常见语音模型，如 `tts`、`stt`、`asr`、`speech`、`voice`、`whisper`、`mimo`、`cosyvoice`、`fish-speech`、`sensevoice`。

如果供应商不支持 `/models` 或列表不完整，仍可手动输入模型 ID。

拉取模型列表也属于外部 AI 供应商访问，服务端会写入 Langfuse span，记录供应商、Base URL、状态和模型数量。非测试环境必须先配置主应用的 `LANGFUSE_PUBLIC_KEY` 与 `LANGFUSE_SECRET_KEY`。

## 默认项规则

默认模型选择遵循：

- 只有模型启用且供应商启用时，才可作为默认项。
- 用户主动设为个人默认时，会取消当前账号同类型其他个人默认项。
- 管理员主动设为通用默认时，只会取消同类型其他通用默认项，不会覆盖任何用户的个人默认。
- 如果账号没有可用个人默认项，会使用同类型管理员通用默认项。
- 如果没有可用个人默认和通用默认，系统会提示缺少默认模型，不再自动选择最早创建的模型。
- 如果已标记默认的模型不可用，对应默认标记会被清空。
